## How the pieces fit
- `#svcCategory` (hidden select) and `#svcSubcategory` (hidden input) hold the answers from the picker. The picker fires a normal `change` event on the select.
- `STCatForms.mount(...)` (called in `post-service.html`) listens to that change, then draws `candidates(category, subcategory)` into `#catFields` and shows `#secDetails`. No schema for the category = section hidden = `details` saved as `null`.
- Answers live in the engine (`M.values`) while the tasker edits. Changing the type of work inside the SAME category keeps answers with the same key; changing category clears them. On save, `validate()` keeps only questions that are shown and valid, then adds `_v: 1`.
- Draft / edit: the page sets category and subcategory, calls `STCatPicker.sync()`, then `STCatForms.setValues(draft.details)`.
- Save: `payload.details = STCatForms.collect()`. If the `details` or `subcategory` column is missing the page retries without it and shows a toast (so a missing SQL step never loses the listing).

## Stage 4: how to add a category (this is the main job)
Add ONE entry to `SCHEMAS` in `js/category-forms.js`, keyed by the category `value` from `categories.js` (note the old values: Repairs is `handyman`, Moving & Delivery is `logistics`, Events is `events`, Beauty is `grooming`, Food & Catering is `hospitality`, Gardening is `landscaping`, IT is `it_tech`, Design is `creative`, Business & Admin is `business`). Nothing else changes: no HTML, no CSS, no page JS.
```js
SCHEMAS.fashion = {
  groups: { sewing: ['Tailoring', 'Dressmaking'] },          // names must be real subcategory names from categories.js
  fields: [
    { key: 'fabric_by', label: 'Who supplies the fabric?', type: 'select', required: true, options: ['Client', 'Me', 'Either'] },
    { key: 'turnaround_days', label: 'Usual turnaround', type: 'number', required: true, min: 1, max: 90, unit: 'days' },
    { key: 'measure_home', label: 'Do you take measurements at the customer\'s home?', type: 'yesno', subs: '@sewing' }
  ]
};
```
Field options: `key` (never rename once live), `label`, `type`, `options`, `required`, `hint`, `placeholder`, `maxLength`, `min`/`max`/`unit`, `subs`, `notSubs`, `when: { key, equals | in }`. A `when` field must come AFTER the field it depends on.
`tests/category-forms.test.js` already checks all pilot schemas; EXTEND its `PILOT` list with each new category. The tests fail if a schema names a subcategory that does not exist, repeats a key, has a select without options, or leaves any subcategory (or Other) with fewer than two questions.

B (DONE, Stage 4b: keys `creative`, `it_tech`, `business`, `education`, `pet`). C (DONE, Stage 4c: keys `events`, `hospitality`, `assistance`, `construction`, `marketing`, `laundry`). ## Stage 6f notes (daily "new tasks for you" email) - replaces matching
- **Owner decision:** do NOT match a task's answers to a service's answers (taskers are meant to send offers). Instead, when a customer posts a task in a category a tasker has a service in, the tasker gets an email like LinkedIn's job alerts. Category level only; the Poster/Tasker answers are not compared.
- **How it works:** `sql/categories/n2-task-alerts.sql` (+ `n2-rollback.sql`). pg_cron job `task-alert-digest` runs `send_task_alert_digests()` every day at 07:00 UTC (08:00 Lagos). For each tasker it finds OPEN tasks from the last 3 days in the same category group as one of their live services, and writes ONE `notifications` row (type `task_digest`, title "New tasks you might be interested in", message = up to 5 lines "title - place - budget (urgent)" + "+ N more that match your services", `data.url` = Find Tasks, filtered to the category when all shown tasks share one). Inserting a notification already sends the email and the phone push (triggers `notifications_email`, `push-notifications`), and those respect the tasker's Email / Phone notification switches. No email when nothing is new.
- **Rules:** best first = same type of work (subcategory) as the service, then urgent, then newest. Skipped: the poster's own tasks, Local Taskers (nobody logs in as them), services with `available = false` or `listing_status <> 'active'`, and the Other category. A task is never sent to the same tasker twice (`task_alert_log`, cleaned after 30 days). All matching tasks are logged, not only the 5 shown. Category is compared by GROUP, so old saved values (plumber, barber...) match through `category_group()`, a SQL copy of `STCat.resolve()`; `tests/task-alerts.test.js` fails if the two drift (add any new alias to the SQL function too).
- **Old behaviour removed:** `postTask` in `js/db.js` used to call `_notifyTaskersOfNewTask` (one notification, therefore one email, per task, exact-string category match, first 50 taskers, never for tasks published later by verification). The call is gone; the function is left unused.
- **Preview before sending:** `select count(distinct user_id) taskers, count(*) matches from public._task_alert_candidates();` sends nothing. To send now: `select public.send_task_alert_digests();` (the first run after install sends a digest to everyone with a match from the last 3 days).
- **NOT known:** how `email_new_notification()` renders the email (its source is not in the project). The message is plain text with line breaks; if the email shows it as one run-on line, the function needs to turn line breaks into `<br>` (or build a real digest template) and the owner must paste its source. Also not tested against the real Supabase and the email was not seen; tested on a scratch Postgres 16 with stand-in tables: 13 tasks and 8 services covering aliases, paused / unavailable / Local Tasker / Other, own tasks, drafts, old tasks, more than 5 matches, a same-day re-run (0 sent) and a next-day run (only the new task).
- **Not built (ask the owner):** a separate "Task alerts" switch (today only the account-wide Email notifications switch turns these off); matching by place (task location is free text, so a Lagos tasker can get Abuja tasks); skipping tasks the tasker has already offered on.
- **Tests:** `node --test tests/*.js tests/*.mjs` = 214 pass (5 new in `tests/task-alerts.test.js`).
