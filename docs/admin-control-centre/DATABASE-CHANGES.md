# Admin Control Centre: database changes (one section per stage, newest last)

All admin SQL is additive, safe to run twice, and has a rollback file. "Written" means the file exists. "Run locally" means run on a scratch Postgres with stand-ins for the Supabase auth schema. "Applied" is only ever said when the owner reports it (owner convention: no error reported = applied, never "tested").

## A1 (2026-11-07): admin identity and permissions
Files: `sql/admin/a1-admin-core.sql`, `a1-rollback.sql`, `a1-tests.sql`, `a1-bootstrap.sql`.
State: written; run locally (see `handoffs/A1.md`); **not run on Supabase**.

| New object | Kind | Notes |
|---|---|---|
| `admin_users` | table | `user_id` references `auth.users` (restrict, never cascade); status `active`/`suspended`/`removed` |

Rollback: `a1-rollback.sql` (it deletes the admin audit log; use only before the admin area is in use).

## A4 (2026-11-08): dashboard summary
Files: `sql/admin/a4-dashboard.sql`, `a4-rollback.sql`. State: written; **not run anywhere** (no Postgres in the build environment).

Rollback: `a4-rollback.sql` (drops the function only).
Guessed (A0 gave no proof): `identity_verifications.status` values `PENDING` and `REVIEW_REQUIRED` mean "waiting for a person"; `users.role` values `customer` and `tasker`; `escrow_payments.platform_fee` is in naira (the site shows `tasker_amount` with a naira sign); `escrow_payments.status` words are shown as stored.

## A6 (2026-11-08): activity log reader
Files: `sql/admin/a6-activity-feed.sql`, `a6-rollback.sql`. State: written; **not run anywhere**.
Three new functions: `admin_activity_feed(p_source, p_outcome, p_search, p_from, p_to, p_security, p_limit, p_offset)` and `admin_activity_detail(p_id)` (browser, both check `audit_logs.view`), `admin_feed_expr(jsonb)` (helper, server only). Read only; no table, view, policy, trigger or existing function changed; no log altered. It merges `admin_audit_log` with `subscription_admin_log`, `subscription_events`, `dispute_events`, `local_booking_events`, `local_tasker_audit_log`, `job_events`. Each older table is optional: missing or unreadable ones are reported as not available. Older tables' column names were NOT proven in A0, so they are read through `to_jsonb(row)` with lists of likely names (`created_at`/`at`, `actor_id`/`admin_id`/`user_id`, `kind`/`event`/`action`, `booking_id`...): a wrong guess gives an empty cell, not an error. Free-text columns of older logs (`job_events.text`/`note`, which can hold chat text) and all `idv_*` tables are deliberately not read. Only the admin log shows reason, previous and new value (through `admin_activity_detail`). Page size 50, hard cap 100, newest first; no total count (a merged count would scan every log).

## A13 (2026-11-08): disputes in the admin area
Files: `sql/admin/a13-disputes.sql`, `a13-rollback.sql`. State: written; **run on a scratch Postgres 16 with stand-ins (33 checks passed, run twice, rollback and re-apply tested); not run on Supabase.** Test files: `docs/admin-control-centre/local-tests/` (`standin.sql`, `a13-local-tests.sql`).
Changes ONE existing object: `public._is_support()` (`CREATE OR REPLACE`, same signature and security settings). The old two ways in (a row in `support_staff`; the SQL editor's `session_user`) are kept word for word; a third is added: `admin_has('disputes.manage')` (an active admin, with two-step when required). It is only wider. Before replacing it the script checks that the current body mentions `support_staff` and `session_user` (as A0 recorded) and refuses with NOT DONE otherwise; it saves the current definition in new table `admin_function_backups` (server only), which the rollback uses.
New: `admin_function_backups` (table), `_admin_dispute_run` (helper, no browser access), and five browser functions that each check the permission with `admin_guard`, call the existing `support_*` function, and write one admin-log row: `admin_dispute_start_review`, `admin_dispute_resolve` (refund outcomes also need `disputes.refund.record`), `admin_dispute_record_refund` (needs both), `admin_dispute_remove_evidence`, `admin_dispute_read_chat`. All arguments are text and are passed on as quoted literals (`format('%L')`), so they take the type the real `support_*` function declares (not seen: the repo has no SQL for them). No table, policy, trigger or other function changed.
Side effect to know (A1 notes said so): `is_local_tasker_admin()` is `_is_support()`, so an admin with `disputes.manage` now also passes the Local Tasker admin reads and `admin_reassign_local_tasker`'s check. Today only Super Admins exist, so nobody is newly allowed; A9 must replace that function's check before a Support Admin is created (A5).
Limit: `disputes.refund.record` is enforced by the `admin_dispute_*` functions and the page. Anyone with `disputes.manage` can still call `support_record_refund` directly, because that function only checks `_is_support()` (its body is not in the repo). The built-in `support` role holds both permissions, so nothing changes today.
