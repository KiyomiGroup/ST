# Stage A8: Regular Taskers (2026-11-10)
1. **Objective.** Regular Taskers screen (spec S05): directory, masked profile with seven tabs (Overview, Services, Offers, Bookings, Reviews, Earnings and wallet, Verification and plan), logged reveal, suspend and restore with a reason. Suspension really blocks the login, the same way as customers.
2. **Done.** Written and tested only against fakes: `sql/admin/a8-taskers.sql` (+ `a8-rollback.sql`), `admin/taskers.html`, `admin/js/admin-taskers.js`, a "Regular Taskers" menu entry (`admin-shell.js`), and the Edge Function `admin-account-action` now takes a `target` (`customer`, the default, or `tasker`) so one function serves both screens (`supabase/functions/` and the one-file copy in `supabase/deploy/`). **The SQL was NOT run anywhere (no Postgres in this build environment; the apt install failed). The function was NOT run in Deno or against real Auth. Nothing deployed.**
3. **First introspect failed, then v2 worked.** `a8-introspect.sql` v1 cast `membership_for_users` as a view; it is a function (`p_user_ids uuid[]` returns `jsonb`). v2 (`sql/admin/a8-introspect.sql`) ran on 2026-11-10 and is the schema used below.
4. **Schema used (real, from that result).** `taskers.id` and `taskers.user_id` are **text** (joins cast `users.id::text`; `taskers.created_at` is text too); **`tasker_profiles` does not exist** (spec S05 named it; the screen does not need it). `services(user_id uuid, service_name, category, price, rate_unit, location, available, listing_status, verified, is_main, rating, reviews_count)`; `task_applications(tasker_id uuid, task_id, status, created_at)`; `reviews(reviewee_id, reviewer_id, rating, comment)`; `wallets(balance, pending_balance)`; `wallet_transactions(type, amount, status, booking_id)`; `withdrawals` and `withdrawal_bank_accounts` (last 4 only); `identity_verifications(subject_kind, status, provider_status, status_reason_codes, liveness_ok, face_match_ok, document_ok)`; `subscriptions`; `idv_takedowns`. `bookings`, `job_disputes`, `coordinators` columns come from A7. **Not introspected and so not used:** `escrow_payments` (earnings are shown from the wallet and withdrawals only).
5. **Database changes.** Run `a8-taskers.sql` once, whole file; last line `DONE: A8 installed`. **No new table** (it reuses `admin_account_flags` from A7, so A7 must be installed). Four internal helpers and five browser functions only: `admin_tasker_list(search, filter, offset)` and `admin_tasker_get(id)` need `taskers.view`; `admin_tasker_reveal(id, field, reason)` needs `pii.reveal` (email, WhatsApp or phone; logs the field name, never the value); `admin_tasker_account_check/record` need `taskers.suspend` and are called by the Edge Function as the caller. **No column, trigger, policy or function on `users`, `taskers`, `services`, `bookings`, wallets, withdrawals, reviews, `task_applications` or the identity tables is touched.** `admin_tasker_get` returns the money part only when the caller also holds `payouts.view`; otherwise `money` is null and the tab is not drawn.
6. **Read only, on purpose.** Nothing on this screen edits a rating, wallet, commission, verification or membership. The membership label (PRO or PREMIUM) comes from the site's own `membership_for_users` and is shown as "Membership", apart from the identity badge. Never returned: street address, full bank account number, identity number, offer message text, applicant phone or WhatsApp on offers, wallet notes and references, bio, `profile_details`, coordinates.
7. **Suspend and restore.** Same order as A7: check (as caller) -> Auth ban or unban -> record. Refused for yourself, any admin login and any coordinator. A login that is both Tasker and customer can be suspended here (the A7 screen sends it here). **Suspension does NOT hide the Tasker's public profile or services**: hiding a service is stage A14 and the services have guard triggers (`services_listing_status_lock`, `zz_m18_services_guard`, `zz_sub_keep_paused_hidden`). The page says so in the confirmation. The confirmation also warns when the Tasker has open or pending bookings. Ban limits are as in A7 (a session already open can work up to about an hour).
8. **Decisions made without you.** (a) "Deactivate" from the spec is not built; suspend and restore cover it, and a permanent deactivation needs a product decision. (b) The A7 Edge Function was extended rather than copying it, so redeploy it once. Old customer calls (no `target`) still work (test 23).
9. **Known gaps.** (a) Services show `listing_status` but the site does not record who paused a listing; the page says so. (b) Offers show status and task title only, never the message. (c) Reviews list the latest 10 comments (300 characters each) written by customers; they are shown as text. (d) `membership_for_users` returns an unverified shape; the helper accepts a map or a list and any other shape means "no label". If a PRO Tasker shows no label, tell me what `select public.membership_for_users(array['<a PRO tasker user id>'::uuid]);` returns. (e) Local Taskers are not excluded by name: a Local Tasker whose `users` row has role `tasker` would appear here; A10 covers them.
