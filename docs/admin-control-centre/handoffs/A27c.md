# Stage A27c: admin script safety (findings S-1 and S-2)  (2026-11-13)

Picked by me when the owner said "pick a next stage": it needs nothing from her and closes two findings of A27 (`handoffs/A27.md`, items S-1, S-2). No SQL, no database change.

1. **S-1 fixed.** The 24 admin pages loaded the Supabase client from `cdn.jsdelivr.net/npm/@supabase/supabase-js@2/...` (floating version, no integrity check). They now load `/admin/vendor/supabase-js-2.119.0.umd.js`, the official `dist/umd/supabase.js` of `@supabase/supabase-js@2.119.0` saved unchanged (version = the newest 2.x, the one `@2` was most likely already serving; npm registry integrity and the file's SHA-256 are in `admin/vendor/README.md` and `SHA256SUMS`). The CDN could not be reached from my build environment to compare byte for byte; the file comes from the npm tarball.
2. **S-2 fixed.** `vercel.json`: the two `/admin` header rules now carry a real Content-Security-Policy instead of `frame-ancestors 'none'` alone: scripts only from this site (no inline, no eval), styles from this site and Google Fonts, fonts from `fonts.gstatic.com`, images from this site, `data:` (the authenticator QR code) and any `https:` (profile pictures and signed evidence links can sit on other hosts), network calls only to this site and the Supabase project (`ftoiqbacutnbjnztguts.supabase.co`, also `wss:`), no frames, no `<base>`, forms only to this site, no plugins. Nothing else in `vercel.json` changed, so the public site is untouched.
3. **Tests.** `local-tests/a27c-csp-test.js <repo root>` (Playwright): **31 checks pass.** Every one of the 24 admin pages loads in Chromium under the exact policy from `vercel.json` with zero violations and no script error; `login.html` also with the REAL vendor client (client created, `auth.getSession` present); the file matches its checksum; no admin page has an inline script, inline handler or style attribute; a negative control shows an injected inline script, a CDN script and a frame are all blocked. Supabase itself was faked. **Not run on the live site; not deployed.** Page flows after the first render were not run under the policy (the A14b etc. page tests are unchanged and do not enforce it).
4. **Known and accepted.** supabase-js contains a Web Worker path used only when realtime workers are switched on; the admin pages do not use realtime, and the policy would block that worker anyway. The public pages still use the floating CDN client (S-1 there is a separate change, not done: it touches the whole site). S-3 (`admin-disputes.js` reads four tables directly) is still open.
5. **Owner: what you do now.** Deploy the folder (it is `vercel.json`, `admin/*.html` and the new `admin/vendor/`). Then open each admin page once while signed in as an admin and check it loads and works (start with Overview, Approvals, Disputes, Profile and the authenticator-app step on login: they use images, QR codes and signed links). **If any page is blank or a button does nothing:** press F12, open Console, copy the red line that says "Content Security Policy" and send it to me; to switch the policy off in the meantime put `"value": "frame-ancestors 'none'"` back in the two Content-Security-Policy lines of `vercel.json` (the pinned client can stay).
