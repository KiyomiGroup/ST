6. **Functions** (all `SECURITY DEFINER`). For `authenticated`: `admin_team_request_change(p_user, p_change, p_roles, p_reason)` with p_change one of `set_roles`, `suspend`, `reactivate`; `admin_team_apply_change(p_approval)`; `admin_role_request_change(p_role, p_permissions, p_reason)`; `admin_role_apply_change(p_approval)`; `admin_team_changes_mine()` (the caller's pending and approved requests of these two actions). Server only: `admin_team_target_version`, `admin_role_target_version`, `admin_is_last_super`. Asking calls `admin_request_approval` (A2) with the current state as `target_version` and the previous value; applying calls `admin_consume_approval` (A2) and the change in ONE transaction, so any failure undoes both.
7. **Rules enforced.** (a) Needs `admin.team.manage` (team) or `admin.roles.manage` (roles). (b) Nobody may change their own roles or status, in either direction (ask and apply). (c) The last active Super Admin cannot lose that role or be suspended (checked on ask and apply; the A1 triggers are the backstop). (d) `set_roles` needs at least one role and only for an active admin; removing access is `suspend`. (e) `reactivate` only from suspended; removed admins are not handled here. (f) `super_admin` permissions cannot be edited; `approvals.decide` can never be given to another role. (g) The requester applies, the approver is a different Super Admin, the request must be approved, unexpired, for the same target, and the target unchanged since (A2 consume rules). (h) Every ask, refusal and change is in `admin_audit_log` (`admin.team.changed`, `admin.role.changed`, refusals as `admin.team.apply` and `admin.role.apply`).
8. **Decisions made.** (a) Three change kinds, one registry action per area (existing rows, not changed). (b) **Suspending also deletes the login's `support_staff` row** (otherwise a suspended Super Admin would keep the old `support.html` and Local Tasker admin reads); **reactivating a Super Admin adds it back** with note `admin reactivated (A5d)`. Reactivated non-Super Admins are not added (nobody but Super Admins is in `support_staff`: see 10c). The audit row says `support_staff: removed | added | unchanged`. (c) The page sends the checked boxes; the server sorts and de-duplicates. (d) Two presses and a reason of 10+ characters for every ask; the second press shows exactly what will be asked. (e) Apply is a separate step, with two presses.
