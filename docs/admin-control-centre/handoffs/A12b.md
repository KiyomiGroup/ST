3. **What the real sources showed (this decided the design).**
   - A booking has **no coordinator of its own**: `_local_booking_follow_assignment(worker)` moves every open booking of a Local Tasker to that worker's current coordinator (and back to `needs_reassignment` when the worker has none). So H1 = move the **worker** with the A9 function `admin_coordinator_assign_local_tasker` (permission, R-SELF and plan-limit guard stay), then call the follow function again (harmless if a trigger already did it) and check the booking followed, or roll everything back.
   - The real unlock `local_booking_code_unlock(booking, reason)` is open only to `is_local_tasker_admin()` (support staff), so an admin cannot call it. `admin_local_booking_unlock` does the same single write (`bookings.code_attempts = 0`; `bookings_guard` lets SECURITY DEFINER code through because `current_user` is not `authenticated`) after stricter checks.
   - Exceptions are written only by the owning coordinator (`local_booking_record_exception`), are immutable (guard trigger) and have **no resolved state**. Columns: `booking_id, kind, request_id, happened_at, recorded_at, coordinator_id, note`. So the queue is **read only** and the note text is never returned. Five `customer_unreachable` rows is the coordinator limit ("Contact an administrator"); an admin cannot lift it (no function does), the queue only shows it.
   - A12a guesses now confirmed: `escrow_payments.booking_id`, `local_booking_events.booking_id`, `local_booking_milestones.booking_id`, `local_booking_exceptions.booking_id`. Still unconfirmed: `job_events.booking_id` and `local_booking_milestones.created_at`.
4. **A bug found by running the SQL (affects A10 and A12a, both already applied).** `v_failed := v_failed || 'booking'` fails on Postgres ("malformed array literal") because the bare literal is read as an array. It only fires inside the "a section could not be read" handler, so it would have turned a partly failing detail into a hard error. Fixed as `|| 'booking'::text` in `a10-local-taskers.sql` (7 places) and `a12a-bookings.sql` (9 places). **Because the fixed files are `create or replace`, the owner re-runs `a10-local-taskers.sql` and `a12a-bookings.sql` (the A12b file already contains the fixed `admin_booking_detail`).** The A10 scratch tests (87) still pass.

9. **Rules enforced.** R-SELF (booking or worker in the acting admin's own coordinator care, or target is the admin's own coordinator account: refused and logged). Reassign: booking must be open; refused for a deactivated coordinator or a full plan (whole move undone, tested). Unlock: refused when the booking is closed or released, disputed or frozen by an open problem report, unpaid, not actually locked (fewer than 3 tries), not Local. Neither writes a price, quote, consent, payment, escrow, wallet or payout row, and neither reads or shows the completion code.
