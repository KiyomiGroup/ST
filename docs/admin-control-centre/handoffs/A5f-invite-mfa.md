# Small change A5f: set up the authenticator app on the invitation page  (2026-11-11)

1. **Why.** A login with no authenticator app cannot open My profile while two-step is required, so each new admin needed `a3c-mfa-off.sql` then `a3c-mfa-on.sql`. Now the set-up happens on the one-time invitation link.
2. **What changed.** `admin/accept-invite.html` (new set-up panel, loads `admin-mfa.js`), `admin/js/admin-accept-invite.js`. After the password is saved and `admin_my_access` says this login is an active admin: if `mfa_required` and the login has no verified authenticator app, the page shows the QR code and set-up key and asks for the 6-digit code; only a correct code continues to `/admin/index.html`. Not required, or already has an app: unchanged. Not an admin: signed out as before. A reload after the password was saved ("same password") carries on to set-up instead of dead-ending.
3. **Security.** Set-up is still never offered on the normal sign-in page (a password alone cannot add a second step). It is offered only on the invitation page, whose one-time link has just proven mailbox control and whose invite was approved by two Super Admins. Unfinished earlier attempts are cleared by `AdminMfa.startEnrol`. All text via textContent; only a Supabase `data:image/svg+xml` QR is drawn.
4. **Tests.** `local-tests/invite-mfa-browser-test.js`: 11 checks against a fake Supabase (set-up step shown, wrong code refused, right code sent for the new factor, not required, already enrolled, not an admin, reload, expired link). `a5e-browser-test.py` still passes (36). NOT run: real Supabase Auth or a real invitation.
5. **Limits.** Does not help accounts created before this change, or a new admin who closes the page before verifying: they are back to the `a3c-mfa-off.sql` / `a3c-mfa-on.sql` routine (or a new invitation).
6. **Owner: what you do now.** Deploy the two files. Test with the next real invitation (or invite a spare address) and tell me whether the QR step appears after the password.
